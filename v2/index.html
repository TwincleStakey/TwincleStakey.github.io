  1. 1깨달음이 쌓인다

    때리고, 막고, 튕겨내면 머리 위에 "+깨달음"이 뜬다(①②). 왼쪽 아래에 지금 경지와 다음 경지가 보인다(③).

  2. 2TAB으로 진행 확인

  3. 3F로 경지 돌파

    깨달음이 가득 차면 "F 경지 돌파"가 뜬다(①). 운기조식 키(②)로 돌파하고, 돌파 중에 맞으면 주화입마에 빠진다.

2.4.1게스트 화면에서는 안 맞는 공격

적용 · 개발 빌드에서 확인

15%91%비도 판정 일치율
59%96%게스트끼리 비도 판정
360ms~1s170ms게스트 화면에서 방장이 늦게 보이는 시간

측정 조건: 같은 PC에서 개발 빌드 두 개, 편도 지연 60±10ms를 일부러 건 상태, 봇끼리 자동 대전. 실제 인터넷 환경 전체를 대표하는 값은 아니다.

문제

게스트로 하면 화면에선 맞은 비도가 피해 없이 지나갔다.

원인

맞는 쪽이 판정하는데 지연 보상이 없었다. 공격자 화면 속 내 위치와 실제 위치가 달랐다.

해결

공격자 화면에 내가 보이던 시점으로 위치를 되돌려 판정한다. 되돌리는 시간은 방장 · 게스트 조합마다 따로 재서 맞췄다.

자세히 보기과정 · 선택지 · 한계 / 그림 · 코드

게스트로 붙으면 화면에서는 분명히 맞은 비도가 피해 없이 지나갔다. 사자후는 기절 표시만 뜨고 피해가 0이었다. 재 보니 비도 일치율이 15%였다. 판정은 맞는 쪽 PC가 하는데 지연을 보정하지 않아서, 공격자 화면 속 내 위치와 실제 위치가 달랐기 때문이다.

판정을 공격자 쪽으로 옮기면 막기 · 튕겨내기처럼 맞는 쪽이 누른 입력이 무시된다. 그래서 판정은 맞는 쪽에 두고 위치만 되돌리기로 했다. 12ms마다 내 위치를 기록해 두고, 다른 PC에서 온 공격은 그 화면에 내가 보이던 시점의 위치로 잰다. 되돌리는 시간은 방장 · 게스트 조합마다 따로 재서 맞췄고, 게스트 쪽 보간은 NGO 기본 Lerp 대신 고정 3틱으로 바꿨다.

비도 일치율은 15%에서 91%로, 게스트끼리는 59%에서 96%로 올랐다. 게스트 화면에서 방장이 늦게 보이던 시간도 최대 1초에서 170ms로 줄었다.

크레딧을 처음 끝까지 돌려 보니 문제가 네 개 한꺼번에 나왔다. 손님이 쓰러지기 전에 화면이 꺼졌고, 아이리스가 까마귀 옆 빈 곳으로 닫혔고, 마지막 라멘이 비어 있었고, 창 둘레에 갈색 띠가 남았다. 한 화면에서 같이 보여서 하나의 문제 같았지만 원인은 전부 달랐다.

화면이 일찍 꺼진 건 노래 길이에 맞춘 이름 카드 타이머가 끝을 정하고 있었기 때문이다. 손님 연출은 매번 길이가 달라서 조금만 늦어도 잘렸다. 화면을 끄는 일은 연출 마지막의 PlayEnding() 하나로 모았다. 빈 라멘은 그릇이 재료를 전부 거절하고 있었다. 개발 키로 크레딧에 바로 들어가면 튜토리얼이 끝나지 않은 상태라, 그릇의 튜토리얼 검사에 막혔다. 크레딧이 시작될 때 튜토리얼을 끝난 것으로 처리했다.

갈색 띠는 세 번 잘못 짚었다. 배경, 검은 판, 밤 배경 그림을 차례로 의심했지만 그대로였다. 그래서 추측을 멈추고, 녹화 스크립트를 만들어 프레임마다 픽셀을 쟀다. 띠는 정확히 480×270, 화면의 절반 크기였다. 크레딧 창(Frame)을 0.5배로 줄인 크기와 같아서, Frame에 맞춰 깔아 둔 비네트가 같이 줄어든 것이었다. 아이리스도 같은 측정으로 찾았다. 까마귀와 아이리스 판은 같은 Frame 안에 있는데 좌표 변환을 한 번 더 걸어서 120칸 밀려 있었다.
