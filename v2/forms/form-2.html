2.3 · 정무대전

구조 한 장

판의 흐름과 체력은 방장이, 맞았는지는 맞는 쪽이, 투사체 출발점은 쏘는 쪽이 정한다.

1 / 3

쏘는 쪽은 출발점만 정한다

투사체는 네트워크 오브젝트가 아니다. 쏘는 사람이 출발점과 방향을 RPC 한 번으로 보내고, 각 PC가 직접 날린다.

2 / 3

맞았는지는 맞는 쪽이 정한다

막기 · 튕겨내기는 맞는 쪽이 누른 입력이라, 판정도 맞는 쪽 PC가 한다. 다른 PC에서 온 공격은 그 화면에 내가 보이던 시점으로 위치를 되돌려 잰다.

3 / 3

체력과 판 흐름은 방장이 정한다

맞는 쪽이 보낸 피해는 방장이 한 번 더 걸러서 체력에 반영한다. 무적 시간을 길게 보고해도 상한 이상은 받지 않는다.

문제

잴 때마다 달라지는 숫자

되감기를 넣은 뒤에도 비도 일치율이 잴 때마다 38~60%로 달랐다. 창 두 개를 띄우면 포커스 없는 에디터가 49초에 3프레임만 돌았다. 프로파일러로 보니 화면 출력 대기가 1초마다 500ms씩 걸리고 있었다.

측정

개발 빌드 두 개로 옮기기

에디터에서만 생기는 멈춤이라, 측정을 개발 빌드 두 개로 옮겼다. 실행 인자 하나로 방장 · 손님 · 자동 대전 · 지연 시뮬 · 일치율 기록을 켤 수 있게 만들었다.

  • 멈춘 구간만 빼고 분석 → 매번 손으로 골라야 한다
  • 개발 빌드 두 개로 측정
원인

던지는 사람 화면만 다른 출발점

숫자가 안정되자 진짜 원인이 보였다. 던지는 사람 화면에서만 비도가 지금 자리에서 출발해 궤적이 최대 0.8m 갈라졌다.

해결

출발점은 쏘는 사람이 보낸다

출발점과 걸음 속도를 RPC로 보내고, 모든 화면이 같은 식으로 자리를 셈하게 했다. 비도 102번 중 93번이 일치했다.

실제로 남긴 원칙시간이 지난 뒤 나가는 암기는 출발점과 방향을 쏘는 사람이 정해 RPC로 보낸다. 새 초식을 넣으면 빌드 두 개로 일치율을 다시 잰다.
코드

바뀐 부분

던지는 순간의 자리와 걸음을 한 번에 보내고, 받는 쪽은 같은 식으로 자리를 셈한다.

AI와 나눈 일 새 기술 구현과 측정 도구 코드는 맡겼고, 판정 원칙 · 측정 방식 · 통과 기준은 직접 정했다.
